# v0.1.32-rc4 - Shared Logs endpoint and delivery diagnostics

This prerelease updates [PR #35](https://github.com/GuanceCloud/obs-agent-connector/pull/35), which remains unmerged. Stable release/CDN pointers are unchanged.

## Changes since RC3

- Remove Codex `otel_logs_url` and `--logs-url`. Logs now use the shared `endpoint` plus relative `logsPath`, with GTrace default `v1/write/otel-logs`. The retired JSON key is ignored by the runtime and removed by normal install/config edits. `update codex` still preserves configuration bytes through `--no-config`.
- Record actual Logs delivery outcomes in `gtrace-hooks.json`: `uploaded logs`, `logs upload failed`, and `logs retry scheduled`. Include HTTP status, signal/source, record/rejection counts, bounded error category, retryability, and persisted next retry time where applicable.
- Keep `gtrace.json` for configuration only. Diagnostics exclude payloads, URLs, credentials, and server response bodies. A diagnostic write failure does not block delivery.
- Preserve existing queue scope for endpoint/path configurations; do not migrate queues that used a retired full-URL destination.

## Validation and acceptance boundary

Tests cover the shared endpoint/path protocol flow, retired URL removal and ignored runtime overrides, rejected CLI flags, configuration preservation, successful delivery, HTTP 403/503, HTTP 200 with partial rejection, durable retry times, no-op passes, privacy, and diagnostic write failure.

**Automatic stock Codex sandbox collection is still not implemented.** An authoritative runtime producer must feed the bridge. Configuration and delivery diagnostics do not supply native lifecycle evidence. Live Guance ingestion/source mapping, inventory materialization, and Trace navigation remain acceptance gates for issue #34.

Versioned downloads include six platform packages, installers, version metadata, and SHA-256 checksums.
