# v0.1.33-rc1 - Enable Codex sandbox observation by default

This prerelease includes the experimental Codex sandbox work in [PR #35](https://github.com/GuanceCloud/obs-agent-connector/pull/35) and retains the mainline Hermes fixes shipped in v0.1.32. PR #35 remains open and unmerged. This RC does not replace the stable release.

## Codex sandbox observation

- Enable sandbox observation by default when `sandbox.enabled` is absent. New GTrace installations write `sandbox.enabled=true` and `logsPath=v1/write/otel-logs`, and register all six lifecycle Hooks.
- Preserve existing explicit `sandbox.enabled=false` values, including defaults written by older installers. Normal updates preserve runtime configuration byte-for-byte. With a missing sandbox switch, update reconciles all six Hooks using the enabled default without rewriting the file.
- Keep relative Logs routing explicit at runtime. Legacy configurations without `logsPath` need a configuration edit; unknown/custom upload profiles are not guessed. Logs reuse the configured endpoint and authentication, with fixed `source=agent_sandbox`.
- Observe verified native Linux Codex PID-namespace instances and report identity, state and lifecycle evidence through OTLP Logs. Associate sandbox events with the actual successfully exported OBS Tool Span and Trace IDs. Missing lifecycle clocks and historical execution context are not invented.
- Keep sandbox collection independent of normal Trace/Metrics delivery. Diagnostics distinguish observer errors from upload failures and report missing Stop/Tool Hook registrations without rewriting shared configuration.

## Installation and upgrade

Install the connector binary at this version, then run `obs-agent-connector install codex` for a new integration or `obs-agent-connector update codex` for an existing integration. Reload existing Codex sessions to load refreshed Hook registrations.

For an older installation with an explicit disabled switch or missing Logs route:

```bash
obs-agent-connector config codex edit \
  --sandbox-enabled=true \
  --logs-path=v1/write/otel-logs
obs-agent-connector update codex
```

Explicit opt-out remains available with `obs-agent-connector config codex edit --sandbox-enabled=false`. The main telemetry switch must also be enabled. The configuration command preserves other routes, authentication and Agent identity.

## Validation and limits

Validation covers full Go tests, vet/build, six-platform release packaging, default installation, explicit opt-out preservation and byte-preserving updates. The real Codex CLI two-session acceptance test installs without `--sandbox-enabled=true` and verifies automatic collection and associations to distinct exported OBS Traces using a local deterministic model fixture.

Automatic native collection remains best-effort Linux PID-namespace polling and can miss very short executions. Other operating systems, Landlock-only isolation and remote sandboxes require an authoritative producer. Product inventory and navigation UI are outside this release.

The release includes six platform archives, shell/PowerShell installers, version metadata and `SHA256SUMS`.
