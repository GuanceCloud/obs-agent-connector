# v0.1.32-rc2 - Visible Codex sandbox Logs configuration

This prerelease adds configuration entry points missing from RC1. It is built
from [PR #35](https://github.com/GuanceCloud/obs-agent-connector/pull/35), which
remains unmerged. It does not promote the stable channel.

## Changes since RC1

- Normal Codex installation now generates visible empty `otel_logs_url` and
  `logsPath` fields, with `sandbox.enabled=false` and `sandbox.max_pending=1024`.
  No unverified GTrace Logs route is guessed.
- `config codex list` displays Logs routes, sandbox defaults, the fixed
  `agent_sandbox` source, and the external runtime-producer requirement, including
  when these keys are absent from an older configuration.
- `install codex` and `config codex edit` accept `--logs-url`, `--logs-path`,
  `--sandbox-enabled`, and `--sandbox-max-pending`. Explicit route changes clear
  the alternative override. Invalid settings are rejected before file writes.
- Existing credentials, Trace/Metrics paths, and unknown settings are preserved.
  Other Agents do not receive Codex sandbox settings. `update codex` continues
  preserving the complete runtime file through `--no-config`.

## Acceptance boundary

**Configuring Logs does not enable automatic stock Codex sandbox collection.**
RC2 retains RC1's experimental runtime bridge and still requires an independently
integrated authoritative producer. The bridge is not automatically started.
Native sandbox instance/lifecycle evidence and live Guance source mapping,
inventory, and Trace navigation remain acceptance gates for issue #34.

An older `gtrace.json` can remain unchanged after a CLI/adapter update. Inspect
the effective defaults with `config codex list`; use an explicit edit to set a
verified full OTLP Logs URL or relative path. The source `agent_sandbox` is fixed
by the bridge. See the [configuration guide](https://github.com/GuanceCloud/obs-agent-connector/blob/v0.1.32-rc2/docs/codex-sandbox-observability.md).

Validation covers configuration visibility, explicit edits, route precedence,
missing endpoint rejection, credential display redaction, pre-install validation,
and `--no-config` preservation, alongside the existing bridge regression suite.
These tests do not establish native producer or live backend acceptance.

Versioned prerelease downloads include all six platform packages, installers,
version metadata, and SHA-256 checksums. Stable release/CDN pointers are unchanged.
