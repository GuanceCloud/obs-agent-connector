# v0.1.32-rc3 - Default Codex GTrace Logs route

This prerelease updates [PR #35](https://github.com/GuanceCloud/obs-agent-connector/pull/35), which remains unmerged. Stable release/CDN pointers are unchanged.

## Changes since RC2

- Codex installation and configuration edits now seed the confirmed GTrace Logs route `v1/write/otel-logs` when the Trace/Metrics paths match the GTrace upload profile. The standard OTLP profile uses `v1/logs`.
- Existing custom Logs paths and full URLs remain intact. Unknown upload profiles require an explicit Logs route. Explicit route edits still override defaults, and `update codex` continues preserving configuration bytes through `--no-config`.
- Logs remain OTLP/HTTP Protobuf with `source=agent_sandbox`. Route defaults do not enable the bridge or start a runtime producer.

For an older installation, add the route without changing the bridge enable state:

```bash
obs-agent-connector config codex edit --logs-path=v1/write/otel-logs
```

## Validation and acceptance boundary

Local tests cover profile defaults, legacy empty route migration during config edits, custom route preservation, explicit empty route resets, pre-install validation, and `--no-config` preservation. A synthetic loopback test runs generated configuration through the Codex resolver and sandbox worker, then decodes the actual gzip OTLP Protobuf request at `/v1/write/otel-logs` and verifies `source=agent_sandbox`. Standard OTLP `/v1/logs` is tested separately.

**Automatic stock Codex sandbox collection is still not implemented.** An independently integrated authoritative runtime producer must feed the experimental bridge. The route is confirmed by backend configuration requirements, but live Guance ingestion/source mapping, inventory materialization, lifecycle history, and Trace navigation remain unverified acceptance gates for issue #34.

Versioned downloads include six platform packages, installers, version metadata, and SHA-256 checksums.
