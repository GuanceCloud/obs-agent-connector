# v0.1.32 - Hermes installation and home-directory fixes

This stable release builds on v0.1.31 and includes [PR #37](https://github.com/GuanceCloud/obs-agent-connector/pull/37).

## Changes

- Honor `HERMES_HOME` throughout Hermes discovery, installed-version detection, configuration lookup, installation, updates, and removal. An unset or empty value falls back to `~/.hermes`.
- Download the published `install.sh` asset for GitHub installation and updates, fixing HTTP 404 errors from the previous installer filename.
- Supply the GitHub release asset base through the Hermes installer's `OSS_ENDPOINT` variable. Despite its name, this variable also selects GitHub release downloads. GitHub and OSS sources remain independent.
- Share environment generation between installer execution and shell command previews. Updates continue to preserve configuration with `--no-config`.
- Keep custom-home removal isolated from the default home and retain runtime configuration unless `--purge-config` is supplied.

## Release scope

This release is built from main after PR #37 was merged. It excludes [PR #35](https://github.com/GuanceCloud/obs-agent-connector/pull/35) and its experimental Codex sandbox OTLP Logs and native Linux observation changes. Earlier v0.1.32 RCs included those experimental changes; this stable release does not promote the RC branch. Existing Codex integration behavior from v0.1.31 is retained.

## Installation and upgrade

Install or update the connector binary to v0.1.32, then run `obs-agent-connector install hermes` for a new integration or `obs-agent-connector update hermes` for an existing integration. Use the same `HERMES_HOME` for each command when using a custom home.

The external Hermes installer owns runtime configuration. Hermes runtime enable/disable remains unsupported because its configuration uses YAML.

The release includes six platform archives, shell/PowerShell installers, version metadata, and `SHA256SUMS`.
