# v0.1.32-rc9 - Diagnose missing Codex Hooks independently of sandbox warnings

This prerelease updates [PR #35](https://github.com/GuanceCloud/obs-agent-connector/pull/35), which remains open and unmerged. Stable release pointers are unchanged.

## Changes since RC8

- Add read-only checks for the connector's Stop, PreToolUse and PostToolUse registrations. The observer reports missing event names and the normal update command when registration changes; it does not rewrite shared Hook configuration or remove another integration's handlers. Stop loss can prevent terminal Trace collection while sandbox Logs keep arriving.
- Add operation names and safe categories to native observer/Hook diagnostics. Routine bounded journal contention is reported as journal_busy only in debug mode; retries continue. Filesystem permissions, missing files, network errors, timeouts and closed connections no longer collapse into the same generic category. No raw paths, URLs, response bodies or credentials are added to these diagnostics.
- Keep sandbox observation/association fail-open with respect to normal Trace and Metrics uploads.

## Validation

Regression coverage includes registration drift with another integration occupying Stop, read-only health checks, safe error classification, and successful deduplicated Trace/Metrics uploads when both sandbox journals are corrupt and observer startup fails, including fail_on_error=true. Existing real Codex host association tests remain applicable. Full Go tests, vet/build, race checks and six-platform packaging are required for this release.

Run update codex using the new connector to reconcile registrations while preserving runtime configuration and unrelated Hooks. Previously missed completed turns can be replayed through the existing terminal collector and upload-state deduplication; missing historical sandbox execution context is not invented. Native automatic collection remains Linux PID-namespace polling and may miss very short executions.
