# obs-agent-connector v0.1.24

## Changes

- Embedded WorkBuddy telemetry into the Go binary, removing the external plugin download and Node.js dependency. Added managed command Hooks, JSONL replay, tool timing, token usage, Skill detection, subagent associations, background uploads, and signal-level retry.
- Added OMP 18.1.15+ integration with a bundled native extension and built-in Go collector, profile-aware lifecycle management, terminal request uploads, parent-child Agent trace correlation, bounded retries, and temporary snapshot cleanup.
- Added CodeBuddy native JSONL transcript support alongside legacy `index.json` sessions, preserving model, per-message usage, and tool-call associations.
- Improved DCode collection with read-only checkpoint enrichment for missing transcript usage and tool metadata, complete available conversation context per LLM call, deduplicated token totals, and causal tool timing.
- Standardized successful built-in span status to OTLP `OK` and failed spans to `ERROR`, including the independent Codex collector. Agent span status follows the terminal turn result.
- Added `obs-agent-connector agents` to list supported Agents and platforms and simplified top-level help.
- Fixed external plugin download-base resolution when the connector is installed from GitHub Releases.
- Refreshed the README with installation steps, the current Agent matrix, common commands, build instructions, and documentation links.

## Compatibility and migration

- This stable release contains changes merged into `main` since v0.1.23. OpenClaw remains an external plugin; the unmerged OpenClaw RC integration is not included.
- To migrate WorkBuddy, run `obs-agent-connector install workbuddy`, then restart WorkBuddy. Legacy configuration and upload markers are preserved. If WorkBuddy overwrites settings on exit, rerun installation while it is closed. WorkBuddy supports macOS and Windows.
- OMP requires 18.1.15 or later. macOS ARM64 has been product-tested; Linux and Windows have build validation only. See [OMP setup and limitations](https://github.com/GuanceCloud/obs-agent-connector/blob/v0.1.24/docs/product-research/omp.md).
- DCode checkpoint recovery targets 0.1.68 and requires Python with DCode dependencies. Missing dependencies, incompatible schemas, unavailable checkpoints, and timeouts fall back to the original transcript. Reconstructed LLM context and estimated timing are labeled; existing uploaded traces are not backfilled. See [DCode checkpoint collection](https://github.com/GuanceCloud/obs-agent-connector/blob/v0.1.24/docs/dcode-checkpoint-collection.md).
- Kiro telemetry still requires interactive V3 TTY sessions (`kiro-cli chat --v3`). Default V2 and `--no-interactive` sessions do not load global Hooks.
- Plugin updates preserve existing configuration. CLI self-update remains available through `obs-agent-connector version -u`.
