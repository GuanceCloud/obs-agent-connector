# v0.1.32-rc5 - Explicit sandbox lifecycle timestamps

This prerelease updates [PR #35](https://github.com/GuanceCloud/obs-agent-connector/pull/35), which remains unmerged. Stable release/CDN pointers are unchanged.

## Changes since RC4

- Rename exported lifecycle timestamps to `sandbox_created_at` and `sandbox_destroyed_at` to distinguish them from platform timestamps. Include both fields as independently queryable OTLP LogRecord attributes as well as in the structured Body.
- Preserve UTC RFC 3339 precision and omit unknown timestamps. Producer NDJSON input still uses `created_at` and `destroyed_at`; historical and already queued records are not rewritten.
- Keep trace-association records free of lifecycle timestamps so a delayed association cannot appear to update sandbox state.

## Validation and acceptance boundary

Tests cover creation, destruction, historical and unknown snapshots, timezone/nanosecond preservation, OTLP encoding/decoding, and trace-association separation, alongside existing regression tests.

Existing live test screenshots confirm four lifecycle events reached Guance, but show `source=codex-sandbox-runtime` rather than the requested `agent_sandbox`, and a Protobuf text rendering of structured Body values. The sender still supplies `source=agent_sandbox`; receiver source mapping and Body rendering remain unresolved acceptance items. This release does not claim to fix them.

Automatic stock Codex sandbox collection is still not implemented. An independently integrated authoritative producer is required. The timestamp change does not add native collection or fabricate Trace relations.

Versioned downloads include six platform packages, installers, version metadata, and SHA-256 checksums.
