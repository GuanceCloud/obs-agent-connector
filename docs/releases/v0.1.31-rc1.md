# v0.1.31-rc1 — QwenWork CN acceptance candidate

Release candidate for QwenWork CN acceptance, not a stable-release recommendation.
Full Windows desktop acceptance remains pending; a subsequent Windows AMD64 user
smoke test passed (see below). Use the versioned RC artifacts built
from the release tag, not earlier uncommitted working-tree previews. This release
does not promote or replace the stable channel.

## Changes

- Add the built-in QwenWork CN adapter with local Hook registration, transcript
  replay, independent trace/metric retry checkpoints and config-preserving updates.
- Enable the native token-reporting flag on normal installation. Merge observed
  per-call usage without summing duplicate snapshots or estimating missing counts.
- Add offline privacy-safe status observations for the profile flag, usage,
  replay, independent upload attempts and pending queue files.
- Export ordered visible Assistant outputs per text-bearing LLM call. Unmeasured
  Assistant output windows use a labelled synthetic 1 ms duration without changing
  LLM timing. Root/Assistant spans do not duplicate LLM token metrics.
- Recognize evidence-backed Skill use and support opt-in native thinking capture.
  Thinking remains off by default and is always suppressed by content-none.
- Encode structured input/output message attributes compatibly with the deployed
  GTrace message viewer while preserving unrelated attributes.
- Add temporary-profile lifecycle and Windows-style quoted/Unicode-path regression
  coverage.

## Verification boundaries and known limitations

The native baseline is QwenWork CN 1.2.5 on macOS arm64. The completed synthetic
RC run on 2026-10-08 verified four parent LLM calls, three visible Assistant outputs
of exactly 1 ms, Write/Read/Agent tools and a Skill child under Read. Parent token
totals matched independently queried backend metrics: input 143146 and output 1283.
Native cache-read usage totalled 107968. Isolated loopback replay of that native
sample verified parentage, thinking off/on/content-none, exact wire values and
duplicate suppression without changing the real profile's privacy settings or
uploading additional reasoning content to the backend.

Fixtures additionally cover usage merging, privacy, output timing, retries and
lifecycle behavior. Native, loopback, backend and UI evidence remain distinct.
See [product research](https://github.com/GuanceCloud/obs-agent-connector/blob/v0.1.31-rc1/docs/product-research/qwenwork-cn.md) for exact evidence.

Known viewer limitation: the native Agent tool result `63` is preserved in decoded
OTLP, backend attributes and the UI attribute panel, but its tool-result preview
is blank. No parser data loss was found; the viewer's exact code-level cause is
not confirmed. This remains open as
[Meegle issue 7130926248](https://project.feishu.cn/67d94b8bcb5582623a9ef7a8/67e4df4a0029e0f8957669f4/detail/7130926248).

Subsequent Windows AMD64 user testing confirmed checksum-verified installation,
profile discovery, Hook installation, numeric usage for one LLM call, accepted
trace/metric uploads and completed replay. This is user-reported smoke evidence,
not independent backend verification or full Windows lifecycle acceptance.
Windows ARM64 desktop execution and enterprise policy remain unverified.
RC1's GitHub `-BinaryOnly` installation without an endpoint requires an explicit
`-PluginBaseUrl https://static.guance.com/agent_plugins` to avoid an empty-URI
fallback error. The subsequent source fix does not replace the published installer.
QwenWork CN itself supports Linux, but this published RC1 excludes its adapter
on Linux. A subsequent source correction enables Linux installation;
it does not change RC1 artifacts or establish native Linux telemetry acceptance.
Pure-generation cancellation, provider terminal failures and nonzero reasoning-token
usage remain unverified. Explicit native child-transcript and parent-tool-ID evidence
was observed, but subagent span collection is not implemented and SubagentStart/Stop
Hook delivery has not been accepted. Child usage is excluded from parent totals.
Unsupported cases must not be inferred from ordinary text or time proximity.
Credits and TTFT are not estimated. HTTP acceptance is not proof of storage or UI
rendering. No existing uploaded traces or completed historical turns are rewritten.

Normal install merges `QODERCN_EXPOSE_TOKEN_USAGE=1` into the user profile dotenv;
restart the desktop worker when needed. Process/project overrides can take
precedence. `update qwenwork-cn` preserves config/dotenv bytes. Removal preserves
the user-owned dotenv while removing connector-managed registration and files.

## Distribution and acceptance

The RC package set contains four macOS/Linux tarballs, Windows AMD64 and ARM64 ZIPs,
installer scripts, version metadata and `SHA256SUMS`. Verify archive contents,
checksums and embedded version before testing the desktop integration. RC artifacts stay
in the versioned channel; stable CDN/latest pointers remain unchanged. Windows user
acceptance and separate approval are required before any stable-release promotion.
