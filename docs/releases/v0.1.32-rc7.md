# v0.1.32-rc7 - Native Linux Codex sandbox observation

This prerelease updates [PR #35](https://github.com/GuanceCloud/obs-agent-connector/pull/35), which remains open and unmerged. Stable release/CDN pointers are unchanged.

## Changes since RC6

- Add automatic observation of real Codex Linux PID-namespace sandbox instances. The observer verifies the Codex namespace-init process, separate kernel namespaces, `no_new_privs`, seccomp filtering, and a Codex executor ancestor. Collection stays within the same OS user and effective `CODEX_HOME`. Full-access tools do not create sandbox resources.
- When sandbox collection is enabled, installation/update registers native lifecycle Hooks to start and recover a detached singleton. Existing endpoint, authentication, identity, and privacy configuration remain preserved during `update codex`. Unrelated Hook handlers and matchers are retained, including mixed groups; uninstall removes the new managed handlers too.
- Emit fixed-source `agent_sandbox` Logs with explicit observer provenance `codex.native.linux.proc`. Discovery and terminal snapshots describe observed sandbox instances. Exact creation/destruction clocks are omitted when unknown; permission/read failures produce observation loss rather than fabricated destruction.
- Associate an instance only when the native thread and exact command digest uniquely match Hook session/turn/tool identifiers. A known native session remains available even when no exact Tool match exists. Actual OBS trace/span IDs are still confirmed by successful Trace export. This correlation is marked `native_thread_command_digest` with inferred confidence; the kernel does not expose a native Tool call ID. Ambiguous or unavailable matches remain unlinked. Commands, results, and environment contents are not persisted.
- Add a bounded durable producer outbox and independent delivery loop. A kernel singleton lock releases automatically on crash; Hooks recover the observer. Configuration disable/destination changes or replacement of the connector executable stop it; inactivity also ends it.
- Fix the 2,048-entry default Tool identity cache becoming permanently full. Evict old recoverable warm-cache entries while protecting unresolved relations; recovery reads only identities needed by pending associations.

## Validation

Tests cover kernel-evidence filtering, PID reuse, exact-command ambiguity, privacy, producer outbox recovery, cache capacity rotation, lifecycle Hook dispatch, mixed-handler preservation and uninstall, alongside existing OTLP/retry tests. The opt-in end-to-end test executes the actual Codex 0.163.0 Linux sandbox helper against a local protobuf receiver, verifies automatic startup, discovery, terminal observation, association to a normally exported OBS Tool span, and automatic shutdown when disabled. It uses a private temporary HOME and a marked transcript fixture, with no model/API credentials or hand-authored sandbox events.

## Acceptance limits

This is best-effort polling (20 ms shortly after Hook activity, 100 ms otherwise), not an exhaustive kernel audit. Very short executions may be missed. Native automatic observation currently supports the Linux PID-namespace path validated above; macOS, Windows, legacy Landlock-only mode, and remote environments need another authoritative producer. Exact creation/destruction timestamps and missed historical instances are not reconstructed. Platform inventory projection and navigation remain deferred.

For an existing installation with sandbox collection enabled, run `obs-agent-connector update codex` once using the new connector to refresh native lifecycle Hooks. Disabled installations remain disabled and keep only the normal Stop registration.

See the [data contract and test procedure](../codex-sandbox-observability.md).
