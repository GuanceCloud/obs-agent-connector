# v0.1.32-rc6 - Sandbox log receiver compatibility

This prerelease updates [PR #35](https://github.com/GuanceCloud/obs-agent-connector/pull/35), which remains unmerged. Stable release/CDN pointers are unchanged.

## Changes since RC5

- Set Resource `log.source=agent_sandbox`, which Guance uses to select the log source. Keep the configured `service.name` independently; no source setting or separate Logs URL is introduced.
- Export the sandbox Body as a readable JSON string instead of a KVList that can appear as protobuf diagnostic text. Preserve independently queryable identity, state, provenance, and prefixed lifecycle-date attributes.
- Include `event_name` as a queryable attribute as well as native OTLP EventName. Generated and delayed trace associations consistently use `obs.sandbox.trace.bound`, INFO severity, and a summary without lifecycle state or dates.
- Apply the corrected wire contract to older pending records without changing their event identities or native clocks. Already ingested records are not rewritten.
- Document the producer, OTLP, and Guance field mapping for subsequent platform design. Platform implementation remains deferred.

## Validation and acceptance boundary

Tests cover all eight event types, source precedence despite configured overrides, JSON Body encoding, exact timestamps, privacy, legacy pending records, and delayed/replayed associations, alongside the existing recovery and transport tests.

A live disposable Docker flow verified four lifecycle records stored with `source=agent_sandbox`, a valid JSON `message`, queryable event types, and exact prefixed lifecycle dates. This is explicit manual runtime evidence, not automatic Codex collection.

A separate two-turn transcript fixture executed probes in one real Docker sandbox. Both association Logs were queried after ingestion and matched the OBS trace/span identities confirmed by successful Hook export. The transcript is a marked acceptance fixture; it does not establish native Codex sandbox discovery. Independent Trace-point retrieval through the tested LLM/T query namespaces and platform navigation remain unverified.

Automatic stock Codex sandbox collection is still not implemented. A separately integrated authoritative producer and its lifecycle management remain required; enabling the bridge alone does not discover sandbox instances. No sandbox creation or destruction is inferred from a Tool or turn boundary. See the [data contract](../codex-sandbox-observability.md) for remaining integration gates.

Versioned downloads include six platform packages, installers, version metadata, and SHA-256 checksums.
