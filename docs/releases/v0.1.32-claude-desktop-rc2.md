## Windows Claude Desktop installation

If the Windows Local AppData folder is unsuitable for staging the administrator
helper, OBS tries the current account's profile folder under the same path and
permission checks. The helper's temporary directory is created with a protected
access list. Registration still uses the Windows UAC prompt.

## Retest an existing Windows RC1 installation

Run this in PowerShell as the account that uses Claude Desktop. The installer
updates the connector and keeps the existing telemetry destination and tags.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -Command {
    $ErrorActionPreference = 'Stop'
    $obsRc = 'https://github.com/GuanceCloud/obs-agent-connector/releases/download/v0.1.32-claude-desktop-rc2'
    $obsInstaller = Join-Path $env:TEMP 'obs-claude-desktop-rc2-install.ps1'
    Invoke-WebRequest -UseBasicParsing -Uri "$obsRc/install.ps1" -OutFile $obsInstaller
    & $obsInstaller -Version 'v0.1.32-claude-desktop-rc2' -DownloadBaseUrl $obsRc -BinaryOnly
}
```

After the installer prints the RC2 version, register the Hook and approve UAC.

```powershell
$obs = Join-Path ([Environment]::GetFolderPath('LocalApplicationData')) 'Programs\obs-agent-connector\bin\obs-agent-connector.exe'
& $obs version --offline
& $obs install claude-desktop --capture-content none
& $obs status claude-desktop
```

Start new local Code and Cowork sessions and confirm one trace for each session
in the Guance test workspace.

## Validation

The release pipeline runs the staging, ACL, and helper pinning regression tests
on Windows. Native desktop Hook loading and Guance ingestion on the target
device are acceptance checks.
