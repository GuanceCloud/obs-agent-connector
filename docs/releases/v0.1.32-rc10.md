# v0.1.32-rc10 - Honor HERMES_HOME throughout the Hermes plugin lifecycle

This prerelease builds on v0.1.32-rc9 and includes the Hermes fix from [PR #37](https://github.com/GuanceCloud/obs-agent-connector/pull/37), addressing [Issue #36](https://github.com/GuanceCloud/obs-agent-connector/issues/36). It retains the Codex native sandbox observation and Hook diagnostics from RC9. PR #37 remains unmerged at publication time.

## Changes since RC9

- Resolve Hermes plugin discovery, installed-version detection, configuration lookup, and removal paths from `HERMES_HOME`. An unset or empty value falls back to `~/.hermes`.
- Pass the resolved home to the external Hermes installer so installation and updates use the same directory as discovery and removal. A leading `~/` is expanded.
- Preserve existing configuration during updates with `--no-config`. Removal keeps `config.yaml` unless `--purge-config` is supplied, and a custom home does not cause removal of the plugin under the default home.
- Document the home-directory behavior and add regression tests for default/custom paths, discovery, installed versions, installer commands, and removal isolation.

## Usage

Use the same home for each lifecycle command:

```bash
export HERMES_HOME="$HOME/custom-hermes"
obs-agent-connector install hermes
obs-agent-connector discover
obs-agent-connector update hermes
obs-agent-connector remove hermes
```

The external `hermes-otel-plugin` installer continues to own Hermes runtime configuration. Hermes runtime enable/disable remains unsupported because its configuration uses YAML. This prerelease does not change stable release pointers.
